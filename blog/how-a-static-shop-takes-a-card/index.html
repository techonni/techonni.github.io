How a static shop takes a card

The walls are HTML. The till is Stripe. The file leaves when the payment lands.

shop.techonni.com is a static site. Pages, CSS, JPEGs. No cart cookie. No customer account. That is on purpose. A shop for files does not need a warehouse theme.

GitHub Pages serves the grid. Each print is a small page with the same plate you saw on the home. When you click Get the print, you leave for Stripe Checkout. That is the only moment the site is not static.

Why Stripe and not a marketplace

A marketplace takes a cut and paints its own checkout. Fine for a first test. Wrong once the shop has a face. The grey plate, the type, the price in euros — that should not turn into a purple form.

Stripe hosts the card fields. I do not see the number. I see a payment and an email. The product on Stripe is the same name as the page: Bauhaus 03, Bauhaus Bundle. Tax is marked as a digital good. Managed payments wanted that code. We set it and moved on.

The thin bit of backend

One serverless route on Vercel creates the Checkout session. It knows the SKU, the test price, the success URL. Success is the same product page with ?paid=1. Cancel is the same page with nothing extra. No “thank you for your purchase” in another skin.

The download button is not in the HTML until that flag is on. Before pay you only see Get the print. After pay you see Download print, or on the bundle page, Download zip. The zip is built in the browser from the seventeen JPEGs already on the site. No second server holds a secret archive.

What this costs to run

The pages are free on GitHub. The function is free on the Vercel hobby plan at this volume. Stripe takes a cut of the sale, not a monthly rent. That is the whole stack: files, a form, a flag.

When the shop grows, the next piece is a webhook that emails the zip so you do not depend on the tab staying open. Until then the path is short on purpose. Pay. Come back. Take the file. Print it when the frame is ready.
